# 什么是 ShadowQUIC？（大白话版）

## 一句话总结

> ShadowQUIC 是一个**代理工具**：你在服务器上装一份，在本地装一份，
> 两边的流量都走一条 QUIC 隧道，**又快、又难被墙**。

## 它是干嘛的？

用大白话说：你在家（或公司）的电脑，想访问某些网站，但直接连不上，
或者太慢、太容易被干扰。ShadowQUIC 帮你把流量"绕路"：

```
你的电脑 → 本地客户端 →（加密 QUIC 隧道）→ 远程服务器 → 真正访问的目标网站
```

远程服务器替你完成访问，再把数据原路传回来。从防火墙的角度看，
你只是和一个"普通的网站"在聊天，看不出你在访问别的东西。

## 它和别的代理有什么区别？

市面上代理很多（SOCKS5、Shadowsocks、V2Ray、Trojan……），ShadowQUIC
的几个独门绝活：

| 特性 | 大白话解释 |
|------|-----------|
| **0-RTT 握手** | 建立连接几乎不用等，一上来就能传数据，打开网页更"跟手" |
| **基于 QUIC** | 用 HTTP/3 同款传输协议，在丢包严重的网络下也稳 |
| **UDP 友好** | 玩游戏、语音、看视频这种 UDP 流量也能走，延迟低 |
| **Full Cone** | 打洞能力强，NAT 后面也能顺利双向通信 |
| **SNI 伪装** | 流量伪装成访问 `cloudflare.com` 之类的知名网站，很难被识别 |
| **免证书** | 因为有伪装，服务器端**不需要**自己申请 TLS 证书 |

> 小知识：它还有一个兄弟协议 **SunnyQUIC**，使用真实 TLS 证书、支持
> 多路径聚合。伪装与多路径各有取舍，见 [FAQ](faq.md)。

## 两个关键词：Server 和 Client

ShadowQUIC 一个程序，两种身份，靠配置文件区分：

- **服务端（Server）**：跑在远程机器上，监听一个端口，等待客户端连进来，
  负责真正帮你访问目标网站。配置里写 `inbound: type: shadowquic`。
- **客户端（Client）**：跑在本地，开一个本地代理端口（比如 SOCKS5
  `127.0.0.1:1089`），把你的流量加密后发给服务器。配置里写
  `outbound: type: shadowquic`。

同一个配置文件里其实**两段都有**：`inbound` 决定"我怎么接流量"，
`outbound` 决定"流量怎么出去"。服务端通常 `inbound` 是 `shadowquic`、
`outbound` 是 `direct`（直连）；客户端反过来，`inbound` 是 `socks`（本地
接流量）、`outbound` 是 `shadowquic`（发往远程）。

## 它也支持其他入站/出站方式

- **入站**（流量怎么进来）：`socks`（本地 SOCKS5 代理）、`shadowquic`、
  `sunnyquic`、`mixed`（SOCKS + HTTP 自适应）、`tproxy`（透明代理）
- **出站**（流量怎么出去）：`shadowquic`、`sunnyquic`、`socks`、`direct`（直连）

## 常见应用场景

- 个人科学上网（客户端在手机/电脑，服务端在海外 VPS）
- 局域网共享（路由器上跑一个，全屋设备共用）
- 游戏加速（UDP 友好 + Full Cone，NAT 类型友好）
